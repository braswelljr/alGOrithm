# Rules

The cross-cutting rules the alGOrithm code and documentation follow, one file each. A rule is a convention that holds across many files, so no single file states it: how packages are laid out, what a doc comment must say, how a test proves an answer, which principles the design follows, how the visualizer treats its users, how work reaches the repository. Each file gives the rule in one sentence, why it exists, what it looks like in the code, and what checks it. Where nothing automated checks a rule, the file says "review".

## Code

| Rule | Statement | Checked by |
|------|-----------|------------|
| [one-package-per-topic](one-package-per-topic.md) | One package per topic under `pkg/`, one file per algorithm, `X` and `TraceX` together | `TestRegistryIsConsistent`; review |
| [the-standard-library-only](the-standard-library-only.md) | The Go module requires nothing outside the standard library and uses no cgo | `go mod verify` in Lint; review of `go.mod` |
| [a-package-returns-its-answer](a-package-returns-its-answer.md) | No printing or reading a terminal outside `internal/cli`; results are returned | `forbidigo` in `.golangci.yml` |
| [the-doc-comment-states-the-cost](the-doc-comment-states-the-cost.md) | Every exported function states its time and space cost, and the registry agrees | `TestRegistryIsConsistent`; review |
| [the-caller-knows-whether-the-input-is-changed](the-caller-knows-whether-the-input-is-changed.md) | The doc comment says "in place" or "returns a new slice", and a test checks it | `check.Sort`; `TestMinHeap` |
| [absent-and-empty-are-told-apart-from-a-value](absent-and-empty-are-told-apart-from-a-value.md) | `-1` for an absent index; `(value, ok)` or an `error` where nothing may be found | `structures` tests; `check.Search`; `TestInputErrors` |
| [new-code-uses-type-parameters](new-code-uses-type-parameters.md) | Generic over `cmp.Ordered`, `comparable` or `any` unless the algorithm needs integers | `TestGenericSortsTakeStrings`; review |
| [a-test-fails-when-the-answer-is-wrong](a-test-fails-when-the-answer-is-wrong.md) | Tests assert, are table-driven, cover edge cases, run under `-race`; sorts and searches use `internal/check` | `go test -race ./...`; review |
| [simulations-are-deterministic](simulations-are-deterministic.md) | Concurrency simulations are seeded and replayable; the real tools are race-tested | `TestRace`, `TestDiningPhilosophers`, `-race` |

## Design

| Rule | Statement | Checked by |
|------|-----------|------------|
| [design-principles](design-principles.md) | KISS, SOLID read for Go, DRY, YAGNI, composition, accept interfaces and return structs | Review; `TestPrinciples`; `TestGeneratedDocsAreCurrent` |
| [access-principles](access-principles.md) | LIFO (FILO), FIFO (LILO) and priority order are interfaces every matching structure satisfies | Compile-time checks; `TestPrinciples` |
| [algorithms-report-events-not-pixels](algorithms-report-events-not-pixels.md) | A traced algorithm records events to a `trace.Recorder` and shares one implementation with the untraced function | `check.Sort` replay; `TestEveryEntryRunsItsExample` |
| [there-is-one-list-of-entries](there-is-one-list-of-entries.md) | `core.Entries()` is the only list of what can run; everything else derives from it | `TestRegistryIsConsistent`, `TestEveryEntryRunsItsExample`, `TestGoSnippetsCompile` |
